# 蛇杖一号 · QQ 机器人 Webhook 方案（不用常驻，腾讯主动推）

> 日期：2026-10-02　作者：毕成
> 主公原话："新消息不用弹窗，收到好简化放到小程序里让大家更方便，不用实时；
> 但机器人不能爬历史信息所以需要常驻在一个地方收。**问微信云端有没有这个功能。**"

---

## 0. 结论

**有，而且比你想要的还省：不用常驻，不用手机开机，不用弹窗。**

QQ 官方机器人**本身就支持 Webhook 回调**——腾讯服务器会主动把群消息 HTTP POST 到你的地址，
**推给你的那一刻才需要你在线**，其余时间什么都不用干。

这一下把"常驻在一个地方收"这个前提给拆了：

> 你说的"需要常驻"，那是 **WebSocket 协议**强加的——长连接得自己一直端着。
> 换成 Webhook，角色倒过来了：**你不需要一直在线，腾讯需要找到你时你在线。**
> 而云端函数天生就是这个形态：没人喊就睡着，一喊立刻跑，跑完就散。

对照你的五条诉求：

| 你的诉求 | Webhook 方案 |
|---|---|
| 新消息不用弹窗 | ✅ 压根没有弹窗这回事（通知栏守卫已按你的要求默认关掉） |
| 收到好、简化放小程序给大家 | ✅ 云函数收到 → 脱敏 → 写云数据库 → 小程序读 |
| 不用实时 | ✅ 完全不用 |
| 需要常驻在一个地方收 | ⚠️ **这条可以取消**：改云函数，不用常驻、不用手机开机 |
| 机器人不能爬历史 | ⚠️ 这是协议限制，**Webhook 也一样补不回历史**，只能"开着就在" |

## 1. 查证到的官方事实

来源：QQ 机器人官方文档 `bot.qq.com/wiki/develop/api-v2/dev-prepare/event-emit/webhook.html`

1. **"QQ 机器人开放平台支持通过使用 HTTP 接口接收事件。开发者可通过管理端设定回调地址，监听事件等。"**
2. 官方产品页明写：**支持 WebSocket、WebHook 回调连接方式灵活切换**。
3. 回调地址**必须是 HTTPS**；**端口只允许 80 / 443 / 8080 / 8443**。
4. 配置完会做一次**回调地址验证**——平台发一个 `plain_token` + `event_ts`，
   要求你用 **Ed25519 私钥签名**后原样返回（不是常见的 HMAC-SHA256，这点错了会全拒收）。
5. 事件推送方式二选一，切了 Webhook 就不需要自己守长连接。

**为什么这比云端云主机更适合你**：云主机（之前放弃那条路）是一台 24h 开的机器，要你维护、
要你防被回收；云函数是**被动触发**，一个月就跑那么几十次，免费额度绰绰有余。

## 2. 新链路

```
QQ群 ──(腾讯服务器主动 HTTP POST)──▶ 云函数 shezhangIngest（URL 化 HTTPS）
                                      ├ 应答回调验证（Ed25519 签名）
                                      ├ 解析群消息 + 脱敏（身份证/手机/学号）
                                      └ 写云数据库 shezhang_items
                                                 │
                                    公告照旧：手机/电脑 push_to_wx.py 每 5 分钟推
                                                 │
                                                 ▼
                                          云数据库（两类数据汇合）
                                                 │
                                                 ▼
                                    微信小程序（全班点开就看）
```

- **群消息**：走 Webhook，腾讯推 → 云函数收（**零常驻、零设备**）
- **公告**：走原来的 `push_to_wx.py`，你手机或电脑连着校园网时推（这段本来就有）
- **展示**：小程序读同一个云库

**全程没有任何一台设备需要 24h 开机。**

### 和"手机 Termux 常驻"对比

| | 手机 Termux 常驻（已备好） | Webhook 云接收 |
|---|---|---|
| 手机要 24h 开机 | 要 | **不要** |
| 收消息耗电 | 每晚几个百分点 | 0 |
| 维护 | 偶尔要重启、要去系统里放行自启 | 0 |
|  freezes 风险 | Android 杀后台 | 无 |
| 成本 | 0 | 云开发免费额度够（个人版 19.9/月，免费体验环境 3000 点/月） |

> 两条路的**共同短板**：都不能补历史（协议不给），都需要机器人处于"已上线"状态。
> 真出问题（比如回调炸了），手机那套还能当备份跑着。

### 🔴 修正二：Cloudflare Workers 小程序为什么读不进来

**不是 CORS，也不是 10ms CPU 的问题 —— 是「域名必须国内 ICP 备案」这一条直接锁死。**

链条（按官方/社区置顶帖查证）：
1. 小程序 `wx.request` **只能访问**「开发设置 → 服务器域名 → request 合法域名」里配过的域名。
   开发者工具的"不校验合法域名"**只在本地调试有效**，真机预览、线上版本强制校验，没得商量。
2. 合法域名必须是**已完成工信部 ICP 备案、且备案主体与小程序主体一致**的国内域名。
   微信开放社区置顶帖明确：用别家备案的域名 → **触发域名校验拦截，所有网络请求被阻止** + 过不了代码审核。
3. `*.workers.dev` 是 Cloudflare 的**境外通配域名，没有国内备案**，格式上（通配）也配不进去。
   → 所以 **Workers 可以当「接收端」，永远当不了「小程序能读的后端」。**

结论：**云函数 URL 化（腾讯云给的那串 `*.service.tcloudb.com` 之类）之所以是唯一省事解，
正是因为域名是腾讯云体系内的，天然在微信白名单里、不用备案、不用买域名。** 这也是它值 19.9/月的原因。

### 端点三选一（修正版）

| | 成本 | 能当接收端（收 QQ 群消息） | 能当小程序后端（给全班读） | 我要改的代码 |
|---|---|---|---|---|
| **① 微信云开发云函数** | 开发期免费；**发布后 15 天到期 → 19.9 元/月** | ✅ | ✅ | 不用改，现成的 |

⚠️ 选 ② 的额外认知：**它是纯粹的"收货口"**。数据落在 Workers 的 KV 里，
但小程序读不到 → 要么再转发一份到云开发（那还不如直接选①），要么就放弃小程序动态展示。
所以 **② 只有在「不打算做小程序」时才成立**。

## 4. 你要做的（约 40 分钟，一次性的）

### 第 1 步：QQ 开放平台切 Webhook（约 15 分钟）

1. 打开 `q.qq.com` → 进你的机器人 → **开发设置**。
2. 找到「事件订阅 / 连接方式」→ 从 **WebSocket（长连接）改成 Webhook（HTTP 回调）**。
3. 回调地址填你云函数 URL 化拿到的 **HTTPS 地址**（端口 80/443/8080/8443 才行）。
4. **事件订阅里勾上群消息事件**（群消息 / at 消息那几项，具体名字后台里看，勾全比省事）。
5. 保存，平台会打一次验证请求——只要你的云函数返回了正确的 `signature`，就显示验证通过。

> ⚠️ 切了之后，**原来的手机 Termux 常驻就收不到群消息了**（连接方式二选一）。
> 所以这两条路是"我全给你备着，你选一条"的关系，不用现在就砍手机那套。

### 第 2 步：云部署（约 20 分钟）

1. `mp.weixin.qq.com` 注册小程序（**个人主体免费**），拿 AppID。
2. 开发 → 云开发 → 建环境。
3. 云函数 → 新建 `shezhangIngest`，把 `shezhangIngest.js` 传上去装依赖。
4. 环境变量填三个：
   - `BOT_SECRET` = **QQ 机器人的 AppSecret**（不是小程序的，别填错）
   - `DEBUG_RAW` = `1`（先开着摸结构，跑顺了改成 0）
   - `WATCH_GROUPS` = 可选，你的群 openid，逗号分隔
5. 云函数 → **配置 → 函数 URL 化** → 开启，拿 HTTPS 地址 → 回填到第 1 步。
6. 云数据库建 `shezhang_items`（权限：所有用户可读，仅管理端可写）、`shezhang_raw`（仅本人看）。

## 5. 五个坑（官方都写了，我提前给你标出来）

1. **端口限制死**：回调地址只能是 80 / 443 / 8080 / 8443，**别配 8081 之类**，会提示不合规。
2. **必须是 HTTPS**：云函数 URL 化天然是 HTTPS，这关自动过。
3. **签名是 Ed25519 不是 HMAC**：网上一大堆 QQ 机器人教程照抄 HMAC-SHA256，照抄必拒收。
   我这儿是按官方 Go 参考实现逐行翻译 + 实测过的。
4. **改了连接方式，旧的长连接就断了**：原来的 `bridge.py run` / 手机 Termux 会立刻收不到消息，
   这是预期行为，别以为是坏了。
5. **群消息事件要在后台勾**：勾错了会导致"连接正常但一条消息都没有"——这是最常见的翻车点，
   现象和 intents 配错一模一样。
