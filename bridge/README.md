## 二、QQ 接入：走官方机器人（不用小号）

### 为什么不用 NapCat 挂小号

主公**是班群和干部群的群主**，这一条把官方路线的唯一门槛解开了。

官方文档 `GROUP_MESSAGE_CREATE`（群消息**全量模式**）写明：

> 当机器人开启了"接收所有消息"功能后，群里的每一条消息（不限于@机器人）都会推送此事件。

所以群里谁随口说一句"周五前交表"，不需要 @机器人，也能被捡出来。
**不用申请 QQ 小号，不用挂第三方协议，不用冒封号风险。**

### IP 白名单不用怕

- **Webhook 模式**：腾讯主动回调你的电脑 → 要固定公网 IP → 校园网 NAT 下会失效。
- **WebSocket 模式**：你的电脑主动连腾讯 → IP 怎么变都无所谓。

**我们用 WebSocket。** 校园网、宿舍网、手机热点都能跑。

### 你要做的三步

1. 用**手机 QQ 扫这个二维码**（你发的那个链接就是机器人的扫码分享页）：
   https://bot.q.qq.com/s/vuL1T8fszK → 打开机器人资料卡 → **添加到群聊**，把机器人拉进班群和干部群。
2. 进群后，在**群设置 → 机器人设置**里把「可访问的消息」设为 **全部群消息**，并打开「允许主动发言」。
   *（这一步是关键，不开就只有 @机器人 才收得到。）*
3. 去 https://q.qq.com → 我的机器人 → **开发设置**，复制 **AppID** 和 **AppSecret**，
   填进 `config.json` 的 `qq_official` 段，把 `enabled` 改成 `true`。

> 关于群号：**不用给我。** 机器人进了哪个群，程序就收哪个群的消息，`watch_groups` 留空即可。
> 如果哪天想只收特定群，再把群的 openid 填进去（运行时日志里能看到）。

> 注意：`https://bot.q.qq.com/s/...` 是**扫码分享页**，不是密钥页。密钥只在开放平台管理端里有。

## 三、Cookie 是什么（附：为什么这次用不上）

**一句话：Cookie 就是网站给你发的"已登录手环"。**

- 你第一次登录统一身份认证平台，输完账号密码，网站说"好，我认得你了"，
  然后往你浏览器里塞一小段数据 —— 这就是 Cookie。
- 之后你打开这个网站的每个页面，浏览器都会自动带上这段数据，网站一看手环就知道"是你，不用再登录了"。
- **它只在你的浏览器里，别人拿不到；有效期一般几小时到几天，过期就要重新登录。**

所以抓需要登录的页面，有两条路：

| 路线 | 做法 | 你要给我什么 |
|---|---|---|
| **A. 模拟登录** | 程序替你填账号密码提交表单，自己拿 Cookie | 账号 + 密码（本机加密存） |
| **B. 复用会话**（更安全） | 你自己先在浏览器登录，我从浏览器导出那张"手环"给你程序用 | **什么都不用给**，我不接触你的密码 |

**这次运气好，你给的两个站都不用登录：**

- 校园官网 https://www.gxmu.edu.cn/
- 图书馆 https://lib.gxmu.edu.cn/

我已经实测直连可抓，Cookie 这条路**暂时不用走**。等哪天要抓教务系统、统一身份认证后面的内容，咱们再上 B 方案。

### 附：如果想改成微信推送

企业微信这条路，多半走不通（不是你的问题）

我查了官方说明，「群机器人」有硬性门槛，缺一条就根本没有这个入口：

- **群必须是企业内部群**。群里只要有个人微信用户（外部群），入口直接消失。
- **只有群主能加**。群若开了「仅群主管理」，管理员和成员都看不到入口。
- **手机端加不了已发布的机器人**，只有电脑端行。
- 管理员可能在后台停用了机器人应用，或开了「限制创建机器人」白名单。

你是个人注册的企业微信，撞上这几条很正常。**别在这上面耗时间。**

### 其实你要的是「推到个人微信」，这跟企业微信是两码事

**PushPlus / Server 酱这类服务直接推到你的个人微信**，不用装企业微信、不用建群、不用公网 IP。
原理前面说过：它们自己有认证服务号，你微信扫码关注 = 授权它替你发。

| 通道 | 怎么弄 | 免费额度 | 推荐 |
|---|---|---|---|
| **PushPlus** | 打开 https://www.pushplus.plus 微信扫码 → 拿 token → 填 `pushplus_token` | 200 条/天 | ⭐ 额度足 |
| **Server 酱³** | 打开 https://sct.ftqq.com 微信扫码 → 拿 `SCT` 开头 key → 填 `serverchan_key` | 5 条/天 | 一天一次也够 |
| **邮件** | 填 `push.email.password`（163 的 **SMTP 授权码**，不是登录密码） | 无限 | 兜底，最稳 |

配置：

```jsonc
"push_channel": "pushplus",          // 想两个一起就写 "pushplus,email"
"push": {
  "pushplus_token": "你的token",
  "email": { "enabled": true, "user": "bicheng2026@163.com", "password": "SMTP授权码" }
}
```

**每天 07:30 自动推**（时刻在 `daily_push_time` 改）。先预览再真发：

```
python bridge.py push --dry      # 只看内容，不真发
python bridge.py push            # 确认没问题再真发
```

> 想拿 163 的 SMTP 授权码：163 邮箱网页版 → 设置 → POP3/SMTP/IMAP → 开启 → 生成授权码。
>
> 隐私提醒：PushPlus / Server 酱会把消息正文过一遍它们自家服务器。
> 学号、证件号这类别写进推送标题。介意的话就只用邮件通道。

## 六、画像过滤：只让相关的事浮上来

官网公告一天几十条，里面大量「人才引进」「图书采购清单」「研究生答辩」—— 跟你一个临床大二班长没关系。

所以加了画像层：公告类内容**必须命中画像关键词**才进待办队列，否则进观测簿。

## 八、这套东西的分寸

- **机器整理，人判断。** 每条都写了「依据」：为什么定这个级、抠出来的截止日是哪天、命中了哪个画像词。你觉得不对就改，改完立刻生效。
- **不沾边的进观测簿。** 没命中关键词、也没截止日、或没命中画像的，进 `noise` 状态，待办队列里看不到，但随时能翻出来回溯。
- **优先级上限。** `max_level` 控制，默认 P3 全收；设成 `P1` 就只放 P0/P1 进来。
- **联网是手动的。** 只有 `crawl` 去抓官网、`push` 去推送。别的都在本机。
- **数据放本机。** `bridge.db` 就在本目录，删了重来。
