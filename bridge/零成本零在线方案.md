## 2. 你要做的（全程点鼠标，不用装东西）

> 括号里是英文原名 —— Cloudflare 的中文界面经常**中英混排**，
> 按钮上写的是中文、旁边或悬停是英文，对不上就按英文名找。

### 第 1 步：注册 Cloudflare
进 `dash.cloudflare.com` 用邮箱注册 → 免费 → 邮箱点验证 → 进控制台。

### 第 2 步：建 Worker 并贴代码（中文界面按钮名）
1. 左边栏点 **Workers 和 Pages**（Workers & Pages）
2. 点 **创建**（或绿色的 **创建应用程序** / Create application）
3. 在列表里选 **创建 Worker**（Create Worker）
4. 名字填 `shezhang`（自己好认就行）→ 点 **部署**（Deploy）
5. 页面自动进到代码编辑器 → 点 **编辑代码**（Edit code）
6. 删掉默认示例，把 `bridge/wx/worker.js` 的**全部内容**粘进去
7. 右上角点 **保存并部署**（Save and Deploy）
8. 部署完给你一个地址，形如 `https://shezhang.xxxx.workers.dev` —— **复制下来给我**

> 刷新后如果回到概览页，点你的 Worker 名字（`shezhang`）就能再进详情页，
> 详情页顶部/左侧会有 **设置**（Settings）和 **编辑代码**（Edit code）两个入口。

### 第 3 步：建 KV 存储（Worker 的"数据库"）—— 只建一次
在 `shezhang` 这个 Worker 的详情页：

1. **设置**（Settings）
2. 找到 **变量**（Variables）那一大块，往下滑，找 **KV 命名空间绑定**（KV Namespace Bindings）
3. 点 **添加绑定**（Add binding）
4. 类型选 **KV 命名空间**（KV Namespace）
5. 变量名（Variable name）填 **`SHEZHANG`** ← **必须全大写、一字不差**，代码里写死了
6. 命名空间下拉里点 **创建新的命名空间**（Create new namespace）→ 名字同样填 `SHEZHANG` → 点 **创建**
7. 回到绑定表单，点 **保存**（或 **添加**）→ 最后整个页面再点一次 **保存并部署**（Save and Deploy）

> 另一个等价走法：不去绑定页，直接在左边栏 **Workers 和 Pages → KV** → **创建命名空间**（Create a namespace）
> → 名字 `SHEZHANG` → **添加**。两条路都行，别建两个命名空间。

### 第 4 步：配 5 个变量（还是同一页，**变量**（Variables）区域，往下滚）
| 变量名（Variable name） | 类型（Type） | 值从哪来 |
|---|---|---|
| `BOT_SECRET` | **加密文本**（Secret） | QQ 机器人后台的 AppSecret（只用于应答 QQ 首次验证的签名，存云端） |
| `PUBKEY` | **变量**（Plain text） | 第 5 步自己算，**64 位十六进制** |
| `ADMIN_TOKEN` | **加密文本**（Secret） | 自己生成：`openssl rand -hex 24` |
| `READ_TOKEN` | **加密文本**（Secret） | 再生成一个，查群消息时用 |
| `WATCH_GROUPS`（可选） | **变量**（Plain text） | 只收指定群，逗号分隔，如 `AbCd1234` |

点 **添加变量**（Add variable / Add plain text）填普通文本，点 **添加加密文本**（Add secret）
填秘密。**名字一个字都不能错**（代码里就是这么读的）。
改完别忘了再点一次 **保存并部署**（Save and Deploy）。

### 第 5 步：本机算公钥（AppSecret 不上传第二处）
在你电脑或手机 Termux 里跑（要 Node ≥16）：
```bash
node bridge/wx/tools/pubkey.js 你的AppSecret
```
会打印一行 `PUBKEY =` 后面 64 个字符，粘到上面第 4 步的 `PUBKEY`。

> 为什么这样：普通群消息的验签用**公钥**就够，AppSecret 只在本地用来生成它。
> 只有「QQ 首次验证回调地址」那一下必须用私钥签名，所以 `BOT_SECRET` 得留在 Worker 里 —— 它只存在 Cloudflare 的加密环境变量里。

### 第 5.5 步：命令行（我就是用这条路部署的 —— 一条命令传代码+KV+4个secret）

不用点界面，在 `bridge/wx/tools/` 下跑：
```bash
python _cf_deploy.py      # 算公钥 → 建/复用 KV → 一次 multipart PUT 传完
python _cf_finish.py      # 取 subdomain 拼地址 + 体检 + 清测试残留
```
**API 侧踩过的三个坑（改代码重传时必看）**：

1. **模块 part 的 Content-Type 必须是 `application/javascript+module`**。
   写成 `application/javascript` → Cloudflare 按 Service Worker 语法解析，报
   `SyntaxError: Unexpected token 'export' at worker.js:251`（我在这上面试了三轮才定位）。
2. **metadata part 的名字必须是 `metadata`**（带下划线 `_metadata` 会报
   `10021 Could not read content for part 'metadata'`）。
3. **secret 不要走独立接口**：`PUT/POST .../scripts/{名}/secrets/{名}` 对 API Token 一律 405
   （`method_not_allowed`）。正确做法是把 secret 塞进 metadata 的 bindings：
   `{"type":"secret_text","name":"BOT_SECRET","text":"..."}` —— 一次 PUT 连代码带变量全传完。
   另有 KV 绑定：`{"type":"kv_namespace","name":"SHEZHANG","namespace_id":"<id>"}`。
4. 拿地址别看 `GET .../workers/scripts/{名}` 里的 `hosts`（新版是空的），
   去 `GET /accounts/{account_id}/workers/subdomain`，返回的键叫 **`subdomain`**（不叫 name）。

> ⚠️ 本机沙箱只能连上 `api.cloudflare.com`，`*.workers.dev` 直连超时、代理 502、
> 公共代理自挂（对照 example.com 同样 522）、DoH 也不通 —— **所以最后一眼只能由主公在自己浏览器里验**。

### ⚠️ 三个最容易卡住的地方
1. **KV 命名空间名字必须是 `SHEZHANG`**，而且你的 Worker 代码里 `env.SHEZHANG` 就是这么读的。
   名字写错 → `/api/health` 里 `has_kv` 是 false，报 "The namespace does not exist"。
2. **改完代码或变量一定要再点「保存并部署」**，光保存文件不算，Cloudflare 要重新部署才生效。
3. **变量名别多空格**：`SHEZHANG`（KV 绑定）和 `BOT_SECRET`/`PUBKEY` 这些必须和上面表格一字不差。

### 第 6 步：QQ 开放平台切成 Webhook（← 主公唯一要动的手）
1. 进 `bot.qq.com` → 你的机器人 → **开发 / 事件订阅**

## 2.5 关于「做成小程序」—— 三道官方硬墙（2026-10-02 查微信官方文档核实）

主公的要求是「不论如何都要做成小程序、功能不能少」。我按官方文档核实了下面这些，
不是我不愿意做，是**平台规则层面就走不通**，得让主公知道要破哪一堵墙才有解。

| 墙 | 官方原文/规则 | 结论 |
|---|---|---|
| ① `web-view` 内嵌网页 | 「个人类型的小程序暂不支持使用」；业务域名「目前小程序内嵌网页能力暂不开放给个人类型账号」 | 个人主体小程序**根本没有 web-view 入口**（后台连配置项都不显示） |
| ② 业务域名（内嵌网页用） | 「域名需经过 ICP 备案」+ 要把校验文件放域名根目录 + 只支持 https、不支持 IP | `*.workers.dev` 境外通配，**不可能备案** |
| ③ 服务器域名（`wx.request` 用） | 同样要求 **已 ICP 备案**的 https 域名 | 小程序也**读不到** Cloudflare |

所以「个人主体 + 一分钱不花 + 功能不缺 + 小程序」四个条件**不可能同时满足**，必须放弃一个：

| 路线 | 要放弃什么 | 大概花费 | 备注 |
|---|---|---|---|
| **A. 个人主体 + 微信云开发** | 放弃「一分钱不花」 | **19.9 元/月**（个人版） | 最省事：`wx.cloud.callFunction` **不需要备案域名**，个人主体直接用。云开发发布后 15 天到期，不转付费环境会被销毁 |
| **B. 企业主体 + 备案域名 + web-view** | 放弃「个人主体」+「一分钱不花」 | 主体认证 + 域名 ~60/年起 + 境内云主机（备案必需）~70/年起 | 可以把 web-view 指向自己的备案域名，页面还是部署在 Cloudflare（省掉服务器） |
| **C. 什么都不改，H5 页面** | 放弃「小程序」 | **0 元** | 微信里点开就是 App 体验，**功能一个不缺**（公告+群消息+去重+脱敏全在），还多一个「不需要审核」的好处 |
| D. 先不做展示层 | — | 0 元 | 群消息照收，等你哪天愿意付费/备案再上界面 |

我的建议：**先按 C 用着**（今天就能用，功能不缺，0 元），
等哪天你愿意每月 19.9 块，直接走 A —— 那时是真小程序，不用备案、不用买域名，
我这边只要把 `worker.js` 的读写换成云函数调用就行，改动量很小。

## 4. 隐私护栏（红线照旧）

- `/api/ann` **只放公告**，带 CORS，公开网页版可读
- `/api/qq` **要 token、且不开 CORS**，任何网页的 JS 都偷不走
- 入库即脱敏：身份证 → `[本人]`，手机 → `[手机]`，学号 → `[学号]`（顺序不能反，反了手机号会被当学号）
- 不存发言人昵称
- 群消息**永远不进 GitHub Pages 公开仓库**（和 2026-09-30 定的红线一致）
