## 二、EdgeOne 和 Cloudflare 的三处关键差异（别硬套）

| | Cloudflare Workers | EdgeOne Pages Functions |
|---|---|---|
| 入口 | `export default { async fetch() }` | **`addEventListener('fetch', e => e.respondWith(...))`** |
| 环境变量 | 函数参数 `env` | **全局 `env`**（直接 `env.BOT_SECRET`） |
| KV 绑定 | `env.SHEZHANG` | **全局 `SHEZHANG`**（不是 `env.SHEZHANG`！） |

⚠️ 第三条最容易踩：官方文档明确写「EdgeOne Pages 的 KV 绑定变量是全局变量，而不是 env 对象的属性」，
写 `env.SHEZHANG.get()` 会 undefined。

## 三、部署步骤（主公点鼠标，我这边给每一步的判断标准）

### 第 1 步：开通 KV（可能需要审核）
控制台顶部导航 → **「存储」→「KV 存储」** → 点「**立即申请**」
- 填写使用场景：写「班级公告与通知的存储，用于小程序/网页版读取」
- 提交后**可能要等审核**。如果卡在审核这一步，先跳到第 2 步把项目建好，回头再绑 KV。

### 第 2 步：建项目
你现在就在「项目」页 → 点「**直接上传**」
- 项目名填 `shezhang`
- 把 `bridge/edgeone/` 整个文件夹压缩成 zip 上传
- 部署完会得到一个 `https://xxx.edgeone.app` 的地址 —— **复制给我**

### 第 3 步：建 KV 命名空间并绑定
「存储」→「KV 存储」→ **创建命名空间**，名字填 **`SHEZHANG`**（必须全大写，代码写死了）
→ 回项目页 → 「KV 存储」→ **绑定命名空间**：
- 选刚建的 `SHEZHANG`
- **变量名填 `SHEZHANG`**（这个是代码里用的名字，必须一字不差）

### 第 4 步：配 4 个环境变量
项目 → 「设置」→「环境变量」→ 逐个添加：

| 变量名 | 类型 | 值 |
|---|---|---|
| `BOT_SECRET` | **Secret** | `<在此填 QQ AppSecret>` |
| `PUBKEY` | String | `<在此填机器人公钥>` |
| `ADMIN_TOKEN` | **Secret** | `<在此填推送口令>` |
| `READ_TOKEN` | **Secret** | `<在此填查询口令>` |

配完点「**部署**」才生效。

## 四、验收（三个链接，按顺序）

假设地址是 `https://xxx.edgeone.app`：

| 打开 | 应该看到 |
|---|---|
| `/api/health` | `{"ok":true,"has_secret":true,...,"has_kv":true}` ← **全 true 才算成功** |
| `/api/page?kind=ann` | 公告页面（手机排版的列表） |
| `/api/page?kind=qq&t=<在此填查询口令>` | 班群消息页面 |

然后去 QQ 后台填回调地址：
```
https://xxx.edgeone.app/api
```
（填 `https://xxx.edgeone.app/api`，**不是**根路径！QQ 只会 POST 到这个地址）

## 六、本机推送公告（EdgeOne 版）

`bridge/wx/push_to_wx.py` 里 `post_worker()` 换成：
```python
def post_worker(url, admin, items):
    base = url.rstrip('/')
    req = urllib.request.Request(
        base + '/api/sync', data=json.dumps({"items": items}).encode(),
        headers={"Content-Type": "application/json", "Authorization": "Bearer " + admin},
        method="POST")
```
然后 `bridge/config.json` 的 `wx.worker_url` 填 EdgeOne 地址。
（**这一步等主公确认地址后我来做**，不用主公手动改。）
